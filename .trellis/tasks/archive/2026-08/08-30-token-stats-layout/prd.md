# Token 统计页统一积分统计布局

## Goal

让 Token 统计页与现有积分统计页共享同一套页面骨架和筛选层级，用户无需重新学习交互位置；同时保留 WorkBuddy 与 CodeBuddy CLI 的独立统计和 Token 专属图表。

## Background / Confirmed facts

- `src/pages/CreditStatsPage.tsx` 已形成当前系统的统计页基准：页面标题与刷新操作位于卡片外；每个内容区使用区块标题 + 卡片；趋势卡片将账号/日期筛选放进 `CardHeader`。
- `src/pages/TokenStatsPage.tsx` 当前把页面标题、来源 Tab 和日期范围放在同一外层区域，日期范围不在趋势卡片内，与积分统计的层级不一致。
- Token 统计数据来自本地 WorkBuddy/CodeBuddy CLI JSONL 聚合 API，来源必须继续分开，不得混算。
- Token 页已有总 Token、缓存命中率、流量趋势、Token 构成、使用热力图、项目/模型排行和高消耗会话等内容，本次主要调整信息层级与筛选位置，不重做统计口径。

## Requirements

1. 页面标题“Token 统计”及更新时间/刷新操作位于卡片外，采用积分统计页的页头间距和排版层级。
2. WorkBuddy 与 CodeBuddy CLI 保持两个独立 Tab，位置与系统页头操作区协调，不进入混合统计卡片。
3. 各统计模块采用“卡片外区块标题 + 卡片内容”的结构，区块标题不再作为卡片内部标题重复展示。
4. 日期范围筛选位于对应趋势统计卡片的卡片内部，选项完全统一为“近 30 天 / 今天 / 近 7 天 / 本月”，并沿用积分统计页的按钮组样式、选中态、间距和可访问状态；不再保留“近 90 天 / 全部”快捷入口。
5. Token 专属数据内容继续保留：总 Token、缓存命中率、输入/输出、流量趋势、缓存构成、小时热力图、项目/模型分布和高消耗会话。
6. WorkBuddy/CodeBuddy 切换、日期切换、刷新、加载、错误、无数据和窄窗口布局均可用；切换来源时不混入另一来源数据。
7. 继续使用现有 shadcn/Radix `Card`、`Button`、`Tabs` 和图表包装组件，颜色、圆角、边框、密度沿用 Rhea 主题。
8. 与积分统计一致，日期按钮只控制趋势卡片；总览、构成、热力图和排行展示当前来源的完整本地历史聚合，来源 Tab 仍控制整页。

## Out of scope

- 不改变本地 JSONL 的 Token 解析口径、缓存字段语义或官方接口行为。
- 不新增账号筛选、模型筛选等积分统计没有对应需求的业务能力；本次只统一布局和日期筛选层级。
- 不删除已有 Token 图表，也不以演示数据替代真实本地数据。

## Acceptance criteria

- [ ] 页面标题、更新时间/刷新操作在任何 Token 卡片外可见。
- [ ] 每个主要统计区块的标题在卡片外，卡片内部不重复显示同一标题。
- [ ] 日期筛选按钮仅在趋势卡片内部出现，且视觉/交互与积分统计页一致。
- [ ] 趋势卡片可在“近 30 天 / 今天 / 近 7 天 / 本月”之间切换，并只改变趋势图与该卡片的范围汇总。
- [ ] WorkBuddy 与 CodeBuddy CLI 可独立切换，切换后所有卡片只显示当前来源数据。
- [ ] 首屏和滚动区域保留总 Token、缓存命中率、趋势、构成、热力图和排行信息，窄窗口无横向溢出。
- [ ] `npm run build`、`cargo test --workspace`、`git diff --check` 通过，并完成 Browser 截图/交互验收。
